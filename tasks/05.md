Quero que você gere automaticamente as **classes ViewHelper** para o meu sistema, conforme as instruções abaixo:

<task>
Gerar os ViewHelpers para um domínio Java, considerando a arquitetura baseada em Front Controller + ViewHelper, utilizando DTOs.
</task>

<context>
- Já existe uma interface chamada `DTO` no pacote `controle/dto`.  
- Todos os DTOs usados nos ViewHelpers DEVEM **estender essa interface**.
- Informe, no início do output, os imports necessários e utilize o pacote exato do DTO referenciado.
</context>

<requirements>
1. Para cada domínio/DTO informado, crie TRÊS pacotes:
    - `.viewhelper.persistencia` → ViewHelper para persistência (criação/atualização)
    - `.viewhelper.busca` → ViewHelper para listagem/busca
    - `.viewhelper.exclusao` → ViewHelper para exclusão
2. Em cada pacote, crie a implementação do ViewHelper correspondente:
    - Exemplo: `UsuarioPersistenciaViewHelper`, `UsuarioBuscaViewHelper`, `UsuarioExclusaoViewHelper`
    - Cada ViewHelper deve implementar a interface `IViewHelper<DTO>`
    - Os métodos devem montar o DTO a partir dos parâmetros do `HttpServletRequest`, conforme o contexto da operação
3. Crie uma **classe `ViewHelperFactory`** com:
    - Um método `obterViewHelper(String operacao, String dominio)` que retorna o ViewHelper correto
    - Use um Map com chave composta (`ChaveComposta`) formada pela operação e domínio
    - `ChaveComposta` deve ser uma classe interna estática, sobrescrever `equals` e `hashCode`
4. A Factory deve ser facilmente extensível para novos domínios e operações
</requirements>

<output>
- Estrutura de pacotes e nomes das classes geradas
- Implementações dos ViewHelpers de exemplo (um para persistência, um para busca, um para exclusão)
- Implementação da `ViewHelperFactory` completa, incluindo o Map de ChaveComposta
- Todos os imports necessários, utilize nomes genéricos para domínio e DTO, ex: `UsuarioDTO`, mas siga o padrão do projeto real se informado
</output>
